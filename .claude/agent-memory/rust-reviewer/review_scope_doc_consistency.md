Phase 制限で未対応にした範囲は、(1) クレート `CLAUDE.md` の「スコープ決定」、
(2) `lib.rs` の `//!` スコープ一覧、(3) 実際に返る `FrontendError` のメッセージ、
の3箇所すべてに現れていることをレビューで確認する。どれか1つにしか無い制限、
またはどこにも書かれず**黙って値を落とす**実装は指摘対象。

**Why:** このプロジェクトは「不正な状態を型で排除する」「診断はどこが・なぜ不正かを
説明する」を設計思想に据えている。スコープ外を黙って読み飛ばすと、エラーにも
ドキュメントにも痕跡が残らないまま不完全な IR ができ、コード生成器がそれを忠実に
誤ったコードへ変換する(#2 のレビューで requestBody の欠落・`responses.default` の
無視・`required` の消失が実際に見つかった。いずれもテストは green だった)。

**How to apply:** OpenAPI / DSL のフロントエンドをレビューするときは、入力仕様側の
フィールドを列挙し「読んでいる / 明示的に拒否している / 黙って無視している」の
3分類に振り分ける。3番目に落ちたものはすべて Critical か High として報告し、
「拒否するか、スコープ文書に明記するか」の二択を提示する(実装方法までは指定しない)。

# コードレビューへの応答方法

PR に付いたレビューコメント(Copilot / 人間レビュアー問わず)へ対応する際は、以下を守る。

## 必須: スレッドへの個別返信

- 修正内容は **PR 本体への総括コメントだけで済ませない**。指摘してきたインラインコメントの
  スレッドそれぞれに対して、GitHub の返信(reply)として個別に返答する
- 返信は `gh api -X POST repos/<owner>/<repo>/pulls/<pr>/comments -f body="..." -F in_reply_to=<comment_id>`
  で行う(`in_reply_to` を指定しない投稿は新規スレッドになり、元の指摘と紐付かないため不可)
- 返信内容には最低限、次を含める: 対応したコミットの短縮 SHA、具体的に何を変更したか
- 全体の背景や設計判断の説明が必要な場合は、個別返信とは別に PR 本体へ総括コメントを
  追加してもよい(個別返信の代替にはならない)

## 複数コメントが同一原因の場合

- rust-reviewer.md のレビュー出力ルールと同様、同一原因(例: 依存ライブラリの排除で
  まとめて解決するもの)であっても、**各スレッドへの返信は省略せず全件に行う**
- 返信本文は使い回してよいが、宛先スレッドごとに個別の返信として投稿する

## 再レビューで新しい指摘が来た場合

- push 後に Copilot 等から新しい指摘が追加されることがある。修正 → 対応コミット → 全スレッド返信、
  のサイクルを指摘が無くなるまで繰り返す
- 対応の要否が不明な指摘(スタイル的な好み等)は `[ask]` 相当として、対応するかどうかの判断を
  返信内に明記する(黙って無視しない)
